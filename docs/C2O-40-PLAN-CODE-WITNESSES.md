## Verified source-level defect: signed provider metadata / replay identity
- The schema declares `source_owner varchar(64)`, `external_event_id varchar(191)`, and `sender_ref varchar(191)` in `SchemaExtension.php`.
- Previously `ProviderWebhookController::inbound` applied `sanitize_text_field` to canonical sender/event identifiers and had no explicit width validation, risking changed/colliding identifiers or database-width failure under signed malformed requests.
- `InboundProviderMetadata::fromPayload` now rejects absent/nonstring/empty/padded/control/invalid UTF-8/over-width required fields and preserves exact signed bytes. Optional `sender_trust` defaults to `unverified` **only when absent**; explicit null/forged levels are rejected.
- `ProviderWebhookController::inbound` uses that validator before constructing requester refs, checking idempotency and persisting receipt.
- `tests/c2o-inbound-provider-metadata.php` executes 35 boundary/negative checks including the initially CI-revealed explicit-null bug; both new C2-O suites are in Composer/CI for PHP 8.1–8.4.
- Both source and tests changed. No schema version bump was required because database columns were unchanged. No actual provider payloads, real database or live webhooks were accessed.
