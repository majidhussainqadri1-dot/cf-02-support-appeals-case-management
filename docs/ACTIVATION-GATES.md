# Conditional Activation Gates

The repository may contain reviewed code before runtime extraction, but the plugin remains fail-closed until every gate is evidenced.

## Mandatory gates

- Founder-approved change-control record targeting plan version `1.0`.
- Explicit runtime switch; installation alone never activates the service.
- Measured case volume, backlog and SLA evidence justifying extraction.
- Named product owner, queue leads, specialists, appeal lead, quality reviewer and privacy/security/clinical liaisons.
- Frozen, versioned owner contracts for Files 00/02/09/17/18/19/20/21/24/25 and conditional boundaries where applicable.
- Data-flow map, threat model, privacy classification, retention schedule and abuse cases.
- Migration, reconciliation, rollback and provider-exit plans.
- Automated unit, contract, security, privacy, accessibility, load and migration tests.
- Staging installation, upgrade, backup/restore and rollback rehearsal.
- Zero known unresolved Critical/High defects and explicit acceptance of any time-bound residual risk.

## Fail-closed behavior

When a gate is missing, no public or agent routes are registered, no support tables are created in Phase C2-A, no jobs/emails/provider calls run, Site Health reports missing evidence, and other platform public reading remains unaffected.
